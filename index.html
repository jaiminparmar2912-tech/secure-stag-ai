How Dual-Layer Security Works

StegoShield merges two complementary security disciplines: Cryptography and Steganography.

1
Password Derivation (PBKDF2)

Your password is salted with 16 cryptographically secure random bytes and processed through 100,000 rounds of PBKDF2 with HMAC-SHA256.

2
Authenticated Encryption (AES-GCM-256)

Your plaintext message is encrypted using AES-GCM with a unique 12-byte initialization vector (IV). An authentication tag guarantees tamper-resistance.

3
LSB (Least Significant Bit) Embedding

The resulting binary payload (header + salt + IV + ciphertext) is split into bits and stored into the lowest bit of the Red, Green, and Blue color channels of each pixel.

4
Zero-Loss Carrier Generation

The altered pixels differ by at most ±1 out of 255 values, which is undetectable to the human eye. The output is strictly saved in lossless PNG format.

Best Practices

Security & Usage Checklist

Why is PNG strictly required?

Lossy compression formats like JPEG optimize file size by discarding high-frequency pixel variations and using Discrete Cosine Transform (DCT) quantization. This permanently destroys the least significant bits. PNG is lossless and preserves every bit byte-for-byte.

Is my message ever sent over the internet?

No. 100% of processing occurs in your local browser engine using HTML5 Canvas and the standard Web Cryptography API (window.crypto.subtle). No servers, external APIs, or data telemetry are ever contacted.

What happens if an incorrect password is entered?

Because AES-GCM is an authenticated cipher mode, attempting decryption with an invalid password triggers an authentication tag mismatch. The system instantly rejects the attempt without exposing corrupted or partial data.

Carrier Capacity Formula

Given an image of width $W$ and height $H$, having 3 color channels (R, G, B):

Capacity (Bytes) = floor((Width × Height × 3) / 8)

For example, a 1920 × 1080 photo can store up to 777.6 Kilobytes of encrypted text!
